# Final Review

## 사용 시점
구현 완료 직후 또는 제출 직전. 시간이 부족할수록 필수 조건부터 확인한다.

## 절차
1. 실제 과제의 `README.md`와 제출 안내에서 필수 조건을 다시 읽는다.
2. 각 조건을 `충족 / 미충족 / 검증 불가`로 분류하고 근거 파일, 화면 또는 테스트를 연결한다.
3. 제출 경로와 파일명, 파일 저장 상태, 실행 진입점을 확인한다.
4. 과제 유형에 맞는 최소 검증을 수행한다. 예: 명령행 실행, 테스트, 샘플 입출력, 브라우저 내 기본 동작.
   - **웹 UI 과제**에 `WEB_SPEC.md`가 있으면 페이지와 라우트, 핵심 사용자 흐름, 공통 UI 요소, 주요 상태(빈 데이터, 로딩, 오류 등)를 실제 구현과 비교한다. 제공 환경의 허용된 브라우저 미리보기에서 가능한 범위만 확인한다. 브라우저 검증을 수행하지 못했다면 미검증으로 표시한다.
   - `WEB_SPEC.md`의 자체 제안사항을 공식 README의 필수 요구사항처럼 취급하지 않는다. 설계 문서와 구현 간 불일치는 구분해서 보고한다.
5. 남은 시간이 적으면 중요 기능의 결함부터 수정하고, 부가 기능 추가는 중단한다.
6. 제출 문서가 요구되는 경우 구현 사실, 선택 이유, 검증 결과와 남은 한계를 일치시킨다.
7. 프로젝트 루트의 `PROGRESS.md`를 확인하고 최종 검증 결과를 **반드시 갱신한다**. 파일이 없으면 생성한다. 기록만으로 완료를 판정하지 않고 실제 파일과 실행 결과를 우선하여 충족 상태, 미검증 항목, 남은 문제와 다음 행동을 기록한다. 단, 공식 과제가 기록 파일 작성을 명시적으로 금지하거나 쓰기가 불가능하면 파일 대신 대화에 보고한다.

## 출력 형식
| 필수 조건 | 상태 | 근거/확인 경로 | 후속 조치 |
|---|---|---|---|
| 실제 README에서 추출 | 충족/미충족/미확인 | 파일, 테스트 등 | 필요한 조치 |

마지막에는 `즉시 수정할 문제`, `미검증`, `제출 직전 확인할 파일`을 짧게 보고한다.

## 경계
- 완료로 판정할 근거가 없다면 미확인으로 표시한다.
- `WEB_SPEC.md`가 없다는 이유만으로 웹 과제가 아닌 프로젝트를 감점 또는 미충족으로 분류하지 않는다.
- 시험 제출을 자동 조작하지 않는다. 응시자가 화면에서 최종 상태를 확인한다.
- 본과제 종료 후 AI 금지 구간인 후속 서술형 답안을 대신 작성하지 않는다.
