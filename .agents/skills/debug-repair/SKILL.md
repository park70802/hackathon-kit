# Debug Repair

## 사용 시점
실제로 발생한 빌드 실패, 예외, 테스트 실패, 데이터 처리 문제, 브라우저 동작 오류가 있을 때 사용한다.

## 절차
1. 오류를 재현하거나 제공된 정확한 로그를 읽는다. 오류 메시지와 발생 경로를 보존한다.
2. 실패 지점, 예상 동작, 실제 동작을 한두 문장으로 정리한다.
3. 관련 파일만 확인하고 가능한 원인을 1~3개로 좁힌다.
4. 가장 위험이 낮은 원인부터 **작은 수정**을 적용한다. 관련 없는 파일과 동작하는 기능을 재작성하지 않는다.
5. 같은 명령 또는 같은 입력으로 다시 검증하고 회귀 여부를 확인한다.
6. 두 차례 유사한 수정으로 해결되지 않으면 새로운 증거를 수집해 가정을 수정한다. 무작정 반복하지 않는다.

## 결과 보고
- 원인: 로그 또는 실행 근거 포함
- 수정: 파일과 변경 요약
- 검증: 명령 및 통과/실패/미실행 상태
- 남은 위험: 있으면 명시

## 경계
- 테스트 실패를 숨기려고 검증 조건을 삭제하거나 약화하지 않는다.
- 외부 네트워크, 권한, 환경 격리, 감독 제한을 우회해서 오류를 해결하지 않는다.
- 테스트를 실행하지 않았다면 성공했다고 주장하지 않는다.
